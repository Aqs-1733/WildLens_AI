# 识境后续优化建议

## 1. 识别模型优化

老师提到的 “ulo 模型” 大概率是 YOLO。建议下一阶段把 YOLO 作为检测和裁剪前置模型，而不是直接替代 BioCLIP 或 SpeciesNet。

推荐路线：

- 使用 YOLO 做目标检测：先找出动物、植物、昆虫、足迹、花、果实、叶片等主体区域。
- 用检测框裁剪主体：减少背景干扰，提高 BioCLIP 和 SpeciesNet 的准确率。
- 对视频使用 YOLO + 跟踪：只对关键目标和关键帧做识别，减少重复推理。
- 使用小模型优先：先用 nano/small 级别模型保证速度，再评估 medium/large 的收益。
- 导出部署格式：训练完成后导出 ONNX；移动端再考虑 NCNN、Core ML、TensorRT、OpenVINO 等。

可参考：

- Ultralytics YOLO26 官方文档：https://docs.ultralytics.com/models/yolo26/
- Ultralytics 导出格式文档：https://docs.ultralytics.com/modes/export/

## 2. 提高识别速度

当前 BioCLIP 是在 400721 个视觉原型中做检索。后续可以重点优化检索速度：

- 建立 ANN 近似最近邻索引，比如 FAISS、HNSW、Annoy。
- 把原型向量从 SQLite 中批量导出为 `float16` 或内存映射文件，启动时加载索引。
- 保留 SQLite 存物种元数据，向量检索交给专门索引。
- 对同一图片做哈希缓存，重复识别直接读取结果。
- 对视频按场景变化抽关键帧，不要每一帧都识别。
- SpeciesNet 高置信时可以先返回结果，BioCLIP 作为后台补充。
- 对低置信、冲突、稀有物种再触发 BioCLIP 全库检索和 AI 复核。

建议识别流程：

```text
图片/视频帧
  -> YOLO 检测主体
  -> 裁剪主体
  -> SpeciesNet 快速判断常见动物
  -> BioCLIP 检索 40 万物种原型
  -> 融合判断
  -> 低置信再进入 AI/人工修正
```

## 3. 提高识别准确率

不要直接用 AI 的回答覆盖训练结果。更稳妥的方法是：

- 建立固定测试集：常见物种、相似物种、稀有物种、植物、昆虫、鸟类、夜间图像、模糊图像都要覆盖。
- 每个物种至少保留一部分图片作为验证集，不能训练完就全部删除。
- 下载训练图可以处理完删除，但要保存图片来源、物种名、向量、结果、是否命中。
- 对错分样本建立 hard negative 数据集，比如夜鹭和池鹭、豹猫和家猫、东北虎和孟加拉虎。
- 主动学习只保存高质量样本，不要把低置信或冲突结果直接写进运行时记忆。
- 对中文名、学名、同物异名建立规范映射，避免一个物种出现多个名称。

建议指标：

- Top1 accuracy
- Top5 accuracy
- 低置信触发复核率
- 同属错分率
- 单张图片平均推理耗时
- 视频每分钟处理耗时

## 4. 视频识别优化

视频部分建议重点做成稳定可演示：

- 上传后自动转 H.264 播放版本，解决浏览器播放失败。
- 按关键帧识别，而不是全帧识别。
- 加入目标跟踪，同一个目标跨帧合并。
- 结果按时间轴展示：什么时候出现了什么物种。
- 识别结果进入和图片相同的观察记录。
- 支持暂停视频时查看当前帧识别结果。
- 长视频用后台任务，不要阻塞前端页面。

推荐流程：

```text
上传视频
  -> 转码为浏览器可播放格式
  -> 抽关键帧
  -> YOLO 检测目标
  -> 跟踪同一目标
  -> 对代表帧做 SpeciesNet/BioCLIP
  -> 时间轴融合
  -> 保存观察记录
```

## 5. 页面和交互优化

当前页面已经能跑，后续主要优化体验：

- 左侧导航继续收敛，避免入口太多。
- 图片识别和视频识别保留在同一个“识别”模块内。
- 识别结果字体继续放大，重点显示中文名、学名、置信度、融合状态。
- 切换页面不丢当前识别结果。
- 所有保存操作给出明确成功提示。
- 社区发帖、评论、点赞要有加载中和失败提示。
- 手机端底部导航要更紧凑，避免按钮文字挤压。
- 物种档案减少兜底话术，优先展示已缓存的 AI 资料和真实观察信息。

## 6. 移动端适配

当前前端技术栈适合继续走跨平台路线。

建议方向：

- Android / iOS：继续使用 Capacitor，把 React 前端打包成移动 App。
- 相机、相册、文件系统、分享等能力走 Capacitor 插件。
- iOS 部署时评估 Core ML 或 ONNX Runtime Mobile。
- Android 部署时评估 ONNX Runtime Mobile、NCNN 或 TensorFlow Lite。
- 鸿蒙：优先做 H5/WebView 适配，后续再考虑 ArkTS 原生壳和系统能力桥接。
- 大模型和 40 万原型库不建议直接塞进首包，可以做首次启动资源包或局域网/内网同步。

可参考：

- Capacitor 官方文档：https://capacitorjs.com/docs
- Capacitor Android 文档：https://capacitorjs.com/docs/android
- Capacitor iOS 文档：https://capacitorjs.com/docs/ios

## 7. 推荐开发优先级

第一优先级：

- 让新同学先跑通前端、后端、SpeciesNet、BioCLIP。
- 修正 `.env` 和本地路径。
- 用 10 张不同物种图片做端到端测试。

第二优先级：

- 引入 YOLO 检测和裁剪。
- 建立 BioCLIP 向量 ANN 索引。
- 优化视频关键帧和转码。

第三优先级：

- 做移动端 Android/iOS 打包。
- 做鸿蒙 WebView 适配。
- 扩大训练和评估集。
- 做演示用 UI 精修。
